JVM-程序计数器

概念

Java虚拟机（JVM）中的程序计数器（Program Counter）是一块较小的内存区域，用于指示当前线程执行的字节码指令地址。每个线程都有自己的程序计数器，是线程私有的，属于线程上下文的一部分。程序计数器在JVM的内存模型中是唯一一个不会发生OutOfMemoryError的区域。

程序计数器的作用和主要特点包括：

  1. 指示下一条指令的执行地址： 程序计数器中存储着当前线程正在执行的字节码指令的地址。它是一个指针，指向方法区中的方法字节码的地址。
  2. 线程切换时的恢复点： 由于程序计数器存储着线程执行的位置信息，所以在线程切换时，JVM可以通过程序计数器快速恢复线程的执行状态。这使得线程切换时的开销相对较小。
  3. 方法间的控制流信息： 程序计数器也用于跟踪方法之间的控制流，包括方法调用、返回地址等信息。对于Java程序来说，方法调用和返回时程序计数器的值都会发生变化。
  4. 多线程并发支持： 每个线程都有自己的程序计数器，使得多线程在执行过程中相互独立，不会互相干扰。一个线程的程序计数器的变化不会影响其他线程的执行。

需要注意的是，程序计数器是JVM中唯一一个在Java虚拟机规范中没有规定任何OutOfMemoryError情况的区域。这是因为程序计数器只是一个指示器，不会占用大量内存，并且随着线程的创建和销毁而动态分配和释放。

总体来说，程序计数器在Java虚拟机中扮演着非常重要的角色，用于支持线程切换、方法调用和控制流等功能。

JVM-类加载子系统

类加载器（Class Loader）

概念

在Java中，类加载器（Class Loader）是负责加载 Java 类字节码文件并将其转换为运行时类的组件。类加载器是Java虚拟机（JVM）的一部分，它负责从文件系统、网络或其他来源加载 Java 类的二进制数据，然后创建对应的类对象。

  1. 引导类加载器（Bootstrap Class Loader）：
    • 位于<JAVA_HOME>/lib目录，是虚拟机的一部分，用本地代码实现。
    • 主要负责加载核心类库，如java.lang、java.util等。由于它是用本地代码实现的，所以在Java中无法直接获取对引导类加载器的引用。
  2. 扩展类加载器（Extension Class Loader）：
    • 由sun.misc.Launcher$ExtClassLoader实现，是sun.misc.Launcher的一部分。
    • 负责加载<JAVA_HOME>/lib/ext目录中的类库，用于扩展JVM的功能。
  3. 应用程序类加载器（Application Class Loader）：
    • 由sun.misc.Launcher$AppClassLoader实现，是sun.misc.Launcher的一部分。
    • 负责加载应用程序classpath下的类。这是大多数Java应用程序默认的类加载器。
  4. 自定义类加载器：
    • 继承自java.lang.ClassLoader类，通过覆盖findClass方法实现自定义的类加载逻辑。
    • 自定义类加载器可以用于实现一些特殊的加载需求，例如从非标准位置加载类、动态生成类等。

双亲委派模型

类加载器的双亲委派模型是Java中用于组织类加载器之间关系的一种机制。该模型的核心思想是，当一个类加载器（Child Class Loader）需要加载类时，它首先将这个任务委派给父加载器（Parent Class Loader）。这一委派过程一直往上，直到达到引导类加载器（Bootstrap Class Loader）。只有在父加载器无法加载该类的情况下，才由当前类加载器尝试加载。

双亲委派模型主要用于保证Java类的加载的有序性、唯一性和安全性。以下是一些双亲委派模型的应用方面：

  1. 防止类的重复加载： 双亲委派模型确保在整个类加载器层次结构中，相同名称的类只会被加载一次。如果一个类加载器已经加载了某个类，那么它的父加载器不会再加载一次相同的类，从而避免了类的重复加载。
  2. 核心类库的安全性： 核心类库由引导类加载器加载，这样可以防止自定义类加载器替代核心类库中的类，确保核心类库的完整性和安全性。
  3. 保证类加载的有序性： 双亲委派模型确保类加载是有序的，即从下到上的加载顺序。当一个类加载器尝试加载一个类时，首先会委派给其父加载器，这种有序性有助于避免类加载的混乱和冲突。
  4. 系统安全性： 通过双亲委派模型，Java可以在运行时确保核心类库的完整性，防止不信任的代码替代核心类，提高系统的安全性。
  5. 避免类加载的混乱： 双亲委派模型避免了不同的类加载器加载相同类名的类，从而防止了类的混乱和冲突。
  6. 实现模块化和隔离： 双亲委派模型支持不同层次的类加载器，这使得在不同的层次上实现模块化和隔离成为可能。例如，不同的Web应用程序可以使用各自的类加载器，实现彼此隔离。

总体而言，双亲委派模型在Java中提供了一种清晰且有序的类加载机制，通过这种机制，Java可以实现类的唯一性、安全性和层次性，为Java应用程序提供了可靠的基础。

沙箱安全机制

Java的沙箱安全机制是一种安全措施，旨在提供一种对Java应用程序执行环境进行限制的方式，以防止恶意代码对系统的不当访问。这种机制通过限制代码在运行时的行为，尤其是对底层系统资源的访问，来提高Java应用程序的安全性。以下是Java的沙箱安全机制的一些关键方面：

  1. 字节码验证： 在Java中，所有的Java类都被编译成字节码，然后由Java虚拟机（JVM）执行。字节码验证是确保字节码的合法性和安全性的过程。在加载类的过程中，JVM会对字节码进行验证，以防止通过恶意手段构造的恶意代码。
  2. 类加载器的双亲委派模型： 双亲委派模型在一定程度上提高了类加载的安全性。核心类库由引导类加载器加载，而应用程序类由应用程序类加载器加载。这种层次结构确保核心类库不容易被替代，从而维护了系统的稳定性和安全性。
  3. 安全管理器（Security Manager）： 安全管理器是Java的一个关键组件，它允许在Java应用程序中定义安全策略。通过安全管理器，可以授予或拒绝代码对系统资源的访问，如文件、网络、系统属性等。开发人员可以通过在应用程序中配置安全策略文件，限制代码的权限。

类的加载过程

概念

Java类的加载过程是指将Java源代码编译成字节码文件（.class 文件）并加载到Java虚拟机（JVM）中运行的整个过程。

步骤

  1. 加载（Loading）：
    • 类的加载是指将类的字节码文件加载到内存中。这个过程由类加载器（ClassLoader）来完成。
    • 类加载器根据类的全限定名（Fully Qualified Name）查找类文件，可以从文件系统、网络或其他来源获取字节码数据。
    • 加载完成后，字节码数据被存储在方法区（Method Area）中，不同类的字节码数据在方法区中占据不同的区域。
  2. 验证（Verification）：
    • 验证阶段确保加载的字节码是合法、符合规范的。这个过程主要包括对字节码格式的验证、符号引用的验证等。
    • 验证阶段是确保类的可靠性和安全性的关键一步。
    • 标准JVM字节码都以CAFE BABE开头
  3. 准备（Preparation）：
    • 在准备阶段，虚拟机为类的静态变量分配内存，并设置默认初始值。
    • 这里分配的内存不包括在代码中显式赋值的部分，只包括那些由系统自动生成的、具有默认值的部分。
  4. 解析（Resolution）：
    • 解析阶段是将类、接口、字段和方法的符号引用解析为直接引用的过程。
    • 在解析阶段，虚拟机将符号引用替换为直接引用，以便后续的执行阶段使用。
  5. 初始化（Initialization）：
    • 在初始化阶段，对类进行初始化。这是类加载过程的最后一步。
    • 在初始化阶段，虚拟机执行类的初始化代码，包括执行静态初始化块和静态变量的赋值。
    • 初始化阶段是类加载中的一个重要阶段，它确保了在使用类之前，类的初始化工作已经完成。

JVM判断两个对象是否为同一个类的两个必要条件：

  1. 类的名称必须完全相同，包括完整包名
  2. 加载它们的类加载器相同

JVM-简介

概念

JVM（Java Virtual Machine）是Java虚拟机的缩写。它是一种能够执行Java字节码的虚拟机，是Java平台的关键组成部分之一。Java程序员使用Java编程语言编写应用程序，这些应用程序在JVM上运行而不是在特定硬件上直接运行。

JVM类型

  1. HotSpot JVM： HotSpot是由Sun Microsystems开发的Java虚拟机，它是Java平台的一部分。HotSpot以其高性能而著称，使用即时编译（JIT）技术将字节码转换为本地机器代码。
  2. JRockit JVM： JRockit是由BEA Systems（现在是Oracle Corporation的一部分）开发的Java虚拟机，专注于提供高性能和低延迟的Java应用程序执行。
  3. IBM J9 JVM： IBM的J9虚拟机是IBM公司的Java虚拟机实现，主要用于IBM的Java运行时环境，例如WebSphere。
  4. OpenJ9： OpenJ9是Eclipse Foundation的项目，也是一个开源的Java虚拟机实现，它具有高性能和低内存占用的特点。
  5. GraalVM： GraalVM是由Oracle Labs开发的一种新型的Java虚拟机，它支持多语言运行时，并且具有即时编译器（Graal编译器），可以提供优越的性能。

主要功能

JVM的主要功能包括：

  1. 字节码执行： Java源代码被编译成字节码，而不是机器特定的代码。JVM负责解释或即时编译这些字节码为机器码，以在底层硬件上执行。
  2. 内存管理： JVM负责管理Java程序的内存，包括堆内存（用于对象分配）和栈内存（用于方法调用和局部变量存储）。
  3. 垃圾回收： JVM提供自动垃圾回收功能，定期清理不再被引用的对象，释放内存。
  4. 即时编译（JIT）： 有些JVM实现采用即时编译技术，将字节码在运行时编译成本地机器码，以提高执行效率。
  5. 安全性： JVM提供安全性特性，包括字节码验证，以确保运行的代码不会违反Java语言规范。

JVM是Java跨平台特性的关键，使得Java程序能够在不同的操作系统上运行，只要有对应的JVM实现。这种跨平台性主要是因为Java程序不直接与底层硬件交互，而是通过JVM提供的抽象层进行交互。

JVM支持的是JVM字节码，任何能够编译成JVM字节码的语言，都可以在JVM上运行。

组成部分

JVM（Java Virtual Machine）的结构主要包括以下几个关键组成部分：

  1. 类加载器（Class Loader）：
    • Bootstrap Class Loader： 负责加载Java核心库，例如java.lang包。
    • Extension Class Loader： 负责加载Java扩展库，例如javax包。
    • Application Class Loader： 负责加载应用程序的类，是最常用的类加载器。
  2. 运行时数据区（Runtime Data Areas）：
    • 方法区（Method Area）： 存储类的结构信息、常量、静态变量等数据。
    • 堆（Heap）： 用于存储对象实例。所有线程共享堆，但是每个线程有自己的私有栈。
    • 栈（Stack）： 每个线程都有一个私有的栈，用于存储局部变量、操作数栈、方法出口等信息。
    • 程序计数器（Program Counter Register）： 记录当前线程执行的字节码指令地址。
    • 本地方法栈（Native Method Stack）： 用于支持Java以外的语言调用Java本地方法。
  3. 执行引擎（Execution Engine）：
    • 解释器（Interpreter）： 逐行解释执行字节码。
    • 即时编译器（Just-In-Time Compiler，JIT）： 将整个字节码编译为本地机器码，提高执行速度。
  4. 本地接口（Native Interface）：
    • 提供了一个接口，允许Java代码调用和被调用本地库中的方法。
  5. 本地方法库（Native Method Libraries）：
    • 包含了一组本地方法的库，这些方法可以通过本地接口调用。

JVM字节码架构

JVM字节码是一种栈式架构。

Java 编译器（javac）将 Java 源代码翻译成字节码（bytecode），而字节码是一种与底层硬件架构无关的中间表示。字节码并不直接与特定硬件架构相关联，因此不涉及具体的计算机体系结构。

字节码采用的是一种栈式架构（stack-based architecture），它基于一种假设，即操作数和操作数结果都存储在一个操作数栈中。这种栈式架构是为了在不同的硬件平台上都能够保持一致性，实现 Java 跨平台执行的目标。字节码的执行是由 Java 虚拟机（JVM）来完成的，JVM 将字节码解释或编译成本地机器代码，以在特定硬件上执行。

排序算法

排序算法是《数据结构与算法》中最基本的算法之一。

排序算法可以分为内部排序和外部排序，内部排序是数据记录在内存中进行排序，而外部排序是因排序的数据很大，一次不能容纳全部的排序记录，在排序过程中需要访问外存。常见的内部排序算法有：插入排序、希尔排序、选择排序、冒泡排序、归并排序、快速排序、堆排序、基数排序等。用一张图概括：

什么是稳定的排序算法：

假定在待排序的记录序列中，存在多个具有相同的关键字的记录，若经过排序，这些记录的相对次序保持不变，即在原序列中，A1=A2，且A1在A2之前，而在排序后的序列中，A1仍在A2之前，则称这种排序算法是稳定的；否则称为不稳定的。

（2）high–，由后向前找比它小的数，找到后挖出此数填前一个坑a[low]中。

（3）low++，由前向后找比它大的数，找到后也挖出此数填到前一个坑a[high]中。

（4）再重复执行②，③二步，直到low==high，将基准数填入a[low]中。

举例说明： 一个无序数组：[4, 3, 7, 5, 10, 9, 1, 6, 8, 2]

（1）随便先挖个坑，就在第一个元素（基准元素）挖坑，挖出来的“萝卜”（第一个元素4）在“篮子”（临时变量）里备用。 挖完之后的数组是这样：[ 坑, 3, 7, 5, 10, 9, 1, 6, 8,2]

（2）挖右坑填左坑：从右边开始，找个比“萝卜”（元素4）小的元素，挖出来，填到前一个坑里面。 填坑之后：[ 2, 3, 7, 5, 10, 9, 1, 6, 8,坑]

（3）挖左坑填右坑：从左边开始，找个比“萝卜”（元素4）大的元素，挖出来，填到右边的坑里面。 填坑之后：[ 2, 3,坑, 5, 10, 9, 1, 6, 8, 7]

（4）挖右坑填左坑：从右边开始，找个比“萝卜”（元素4）小的元素，挖出来，填到前一个坑里面。 填坑之后：[ 2, 3, 1, 5, 10, 9,坑, 6, 8, 7]

（5）挖左坑填右坑：从左边开始，找个比“萝卜”（元素4）大的元素，挖出来，填到右边的坑里面。 填坑之后：[ 2, 3, 1,坑, 10, 9, 5, 6, 8, 7]

（6）挖右坑填左坑：从右边开始，找个比“萝卜”（元素4）小的元素，挖出来，填到前一个坑里面，这一次找坑的过程中，找到了上一次挖的坑了，说明可以停了，用篮子里的的萝卜，把这个坑填了就行了，并且返回这个坑的位置，作为分而治之的中轴线。 填坑之后：[ 2, 3, 1, 4, 10, 9, 5, 6, 8, 7]

归并排序

归并排序（MERGE-SORT）是建立在归并操作上的一种有效的排序算法,该算法是采用分治法（Divide and Conquer）的一个非常典型的应用。

基本思想：

归并排序的基本思想是将两个或以上的有序列表合并成一个有序列表。即把待排序序列分为若干个子序列，每个子序列是有序的。然后再把有序子序列合并为整体有序序列。

Typora配置GitHub图床

Typora配置GitHub图床

背景

当我们想要把本地记录的笔记上传至博客等网站时，会发现本地保存图片的url无法直接解析。如果上传图片，需要手动将本地的图片单独上传，十分麻烦。

解决方案

为了解决这个问题，我们在服务端设置一个图床。在使用Typora保存图片时，Typora自动将图片上传至图床并转换成url保存下来，后续想要上传笔记至博客只需要直接复制粘贴即可，十分方便。

操作步骤

  • Github创建图床
  • Github配置token
  • 配置PicGo

一、Github创建图床

github

登录账户，创建一个新的仓库，仓库配置都不重要，只要有个仓库就行。

二、Github配置token

1、点进账户设置

2、拉到页面最下方，选择developer setting

3、选择generate new token(classic)

4、配置token的具体信息

5、生成完毕之后，页面会显示token的值，记录并保存下来，因为为了token的安全性，后续再次打开这个页面不会再显示了。

三、配置PicGo

PicGo is Here

1、下载并安装PicGo，我的安装路径为D:/PicGo

2、打开PicGo，选择图床设置/GitHub

3、设置仓库名为你的Github账户名/GitHub图床仓库名

4、设定分支为master或其他你想用来存图片的分支

5、设定Token

6、点进Typora偏好设置\图像，进行对应配置

7、验证图片上传选项，PicGo会向你的图床传输几张图片用以验证，若运行结果为success，则图床配置成功
